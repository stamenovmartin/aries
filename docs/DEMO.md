# ARIES — демо, извршување и документација

Ова е локално Linux демо со вистински HTTP сервис, GTK интерфејс,
GNOME интеграција, трајна редица за задачи и локален модел. Доказ за
извршување се зачуваните резултати и проверената состојба, а не одговорот на моделот.

## Стартување

Од директориумот `aries`:

```bash
systemctl --user start aries-core.service
./scripts/aries-ui
./scripts/aries-demo          # целосен жив тек, со Firefox, интернет и модел
./scripts/aries-research      # повторлива offline научна споредба
```

`./scripts/aries-demo --core` ги проверува фајловите, workflow, health и
евалуациите без browser и news сценаријата. Потребен е активен ARIES API.
Целосниот тек обично трае неколку минути; секоја задача има ограничено чекање.
Резултатите се во нов директориум `experiments/demo/<run>/`, со JSON и Markdown.
Секој неуспех останува во извештајот; командата завршува со ненулти код ако нешто
не помине. API адресата може да се зададе со `ARIES_API`.

Демото создава сопствена папка `~/Documents/ARIES-Demo-<run>` и ја задржува за
преглед. Не инсталира пакети и не брише лични фајлови. Firefox останува отворен;
привремениот browser на агентот се чисти според постојната ownership политика.

## Сценарио за презентација, 8–10 минути

1. Отвори ARIES и Monitor: прикажи задачи, состојби и докази.
2. Во Automations прикажи schedule, enabled, history и Run now за System Health.
3. Изврши `./scripts/aries-demo`: создавање и независна проверка на фајл,
   читање → листање папка → system status, а потоа намерно непостоечки фајл.
   Последниот случај треба да биде пријавен како неуспешна задача и успешна
   негативна контрола во демото.
4. Прикажи News Radar и Morning Brief, со извори и забележани проблеми при fetch.
5. Во командната лента внеси
   `do task Open https://www.python.org and report the page title`.
   Во Monitor прикажи моделска одлука, browser_open и набљудуваниот наслов.
6. Внеси `evaluate tasks` за оперативната историја и `evaluate learning` за
   контролирана споредба на retrieval верзии. Тоа се две различни мерења.
7. Прикажи JSON резултат и ограничувањата од [научниот протокол](RESEARCH_DEMO.md).

## Што прават автоматизациите и агентот

| Патека | Реално однесување | Доказ |
|---|---|---|
| System Health | probes → оценка → известување кога е потребно | automation run и findings |
| News Radar | collect → cluster → verify → rank → deliver | извори, грешки и workflow decisions |
| Morning Brief | собирање информации и составување преглед | task/run и содржина |
| Topic Dashboards | закажува research задачи за конфигурирани теми | run + goal IDs; pending задачите се користат повторно |
| Bounded workflow | до шест чекори со capability проверки | резултат за секој чекор |
| Agent task | локален модел избира следен дозволен чекор од набљудувања | planner usage, чекори и ограничувања |
| Learning comparison | две lexical retrieval верзии на исти 20 случаи | labels, selections, digests, статистика |

Рачно „Run now“ не ја менува поставката за автоматско извршување. Scheduler
извршува само овозможени автоматизации. Автоматизација што закажала задачи не
значи дека тие веќе завршиле; конечните резултати се во Monitor.

## Linux поправки и дијагностика

На 17 септември 2026 беа поправени два живи дефекта: workspace poll зависеше
од timestamp што беше во иднината по корекција на системскиот часовник, и
Topic Dashboards не запишуваше run, поради што dispatcher повторуваше закажување
секоја минута. Сега poll работи со cadence на asyncio, refresh запишува историја,
ги користи повторно pending темите и остава три места за интерактивни задачи.
Постоечките задачи се зачувани и редицата повторно се обработува.

Dispatcher poll исто така продолжува по корекција на часовникот. За директните
автоматизации runner додава history запис кога самата автоматизација не го
запишала, без дуплирање на веќе запишаните runs. Интервалите со единица `hours`
се претвораат во минути: learning со 24 часа сега се прикажува како 1440 минути.

Зачувани проверки од оваа сесија:

| Проверка | Резултат | Артефакт |
|---|---|---|
| Целосно живо демо | 11/11 | `experiments/demo/20260917T185011Z-72477e/` |
| Core по последните schedule поправки | 7/7 | `experiments/demo/20260917T185338Z-04f0a5/` |
| Целосен тест-пакет | ALL SUITES PASSED | `experiments/demo/validation-20260917/full-suite.log` |
| Последни automation и поврзани регресии | сите поминаа | `experiments/demo/validation-20260917/` |
| GNOME изолиран harness | ALL PASSED | `shell.log` во validation папката |
| Native UI навигација | 8/8 | `ui.log` во validation папката |

Целосниот тест-пакет е извршен пред последната мала schedule поправка;
по неа се повторени automation, API, learning, lifecycle, power и runtime
пакетите и живото core демо. Првите неуспешни демо обиди исто така се зачувани.

Проверката на Firefox сега го користи точниот инсталиран desktop ID, вклучувајќи
`firefox_firefox.desktop` кај Snap; насловот на прозорецот не служи како идентитет.
`operator.settle_seconds` останува 8 секунди. Browser DOM чекањето е ограничено на 45 секунди за страници
со блокирачки scripts; мрежните проверки и ограничувања остануваат активни.

```bash
./scripts/aries-smoke
./scripts/aries-e2e section-check
./scripts/test.sh
./scripts/test-shell.sh
journalctl --user -u aries-core.service -n 80
```

Во тековната login сесија GNOME ја има старата верзија на extension-от, без
новиот `FocusWindow` метод. Новиот shell е инсталиран преку symlink и проверен
во изолираниот GNOME harness, вклучувајќи restore/focus и одбивање погрешен ID.
Потребно е нормално одјавување и повторно најавување за да се вчита новиот код.
Сесијата не се прекинува автоматски: зачувај ја работата пред одјавување.
До тогаш фокусирањето постоечки прозорец може да не успее; smoke го покажува тоа.

## Граници на демото

Ова не е општ автономен оператор за секоја Linux апликација. Browser користи
ограничен јавен GET транспорт; логирање, произволни POST операции и непознати
контроли не се автоматски поддржани. Инсталации и деструктивни операции ги
задржуваат проверките и approval патеките. Интернет и локален модел може да
бидат недостапни; partial/failed резултатите не се претставуваат како done.
Learning не е тренирање на тежини или RL. Продукциски код не се препишува сам.
